#### Prevent complaints from exceeding the purchased quantity ([#4959](https://github.com/shopsys/shopsys/pull/4959))

- if you have overridden `Shopsys\FrontendApiBundle\Model\Complaint\ComplaintApiFacade::create()`, update it accordingly — the remaining quantities are now validated via `validateComplaintQuantities()`
- method `Shopsys\FrontendApiBundle\Model\Complaint\ComplaintApiFacade::validateComplaintItem()` no longer accepts the `$complaintItemInputData` parameter and no longer validates the quantity, the quantity is validated by `Shopsys\FrontendApiBundle\Model\Complaint\ComplaintApiFacade::validateComplaintQuantities()` instead
- the products claimed by a complaint are released for new complaints only when the complaint is in a status of type `ComplaintStatusTypeEnum::STATUS_TYPE_RESOLVED_CLAIMABLE_AGAIN`, review your complaint statuses in administration and set this type on the ones meaning that the products can be complained about again (e.g. rejected or repaired complaints), the default `resolved` status and all existing custom statuses (type `in_progress`) keep the products claimed
- the migration `Shopsys\FrameworkBundle\Migrations\Version20261119110000` adds the complaint status "Rejected" of type `ComplaintStatusTypeEnum::STATUS_TYPE_RESOLVED_CLAIMABLE_AGAIN` including its mail template on all domains, if you do not want this status, skip the migration in your `migrations-lock.yml` (`skip: true`, see [Reordering and skipping migrations](https://docs.shopsys.com/en/latest/introduction/database-migrations/#reordering-and-skipping-migrations)), the demo data fixture `ComplaintStatusDataFixture` creates the status itself when it is missing, so adjust it in your project if you skip the migration and do not want the status in the demo data
- the complaint's `resolution` was renamed to `preferredResolution` to make clear that it is the resolution preferred by the customer, update your code accordingly:
    - `Shopsys\FrameworkBundle\Model\Complaint\Complaint::getResolution()` was renamed to `getPreferredResolution()` and the `complaints.resolution` column to `preferred_resolution` (a migration is included)
    - `Shopsys\FrameworkBundle\Model\Complaint\ComplaintData::$resolution` was renamed to `$preferredResolution`
    - the `resolution` field of the `Complaint` GraphQL type and of the `ComplaintInput` input type was renamed to `preferredResolution`
- see #project-base-diff to update your project
