#### Fixed security issues of uploaded files, access token cookie, GoPay notification and registration lookups ([#5013](https://github.com/shopsys/shopsys/pull/5013))

- `Shopsys\FrameworkBundle\Component\UploadedFile\UploadedFileFacade::isUploadedFileViewableInBrowser()` and the `VIEWABLE_EXTENSIONS` constant were moved to `Shopsys\FrameworkBundle\Component\AbstractUploadedFile\AbstractUploadedFileFacade`, the method now accepts `Shopsys\FrameworkBundle\Component\AbstractUploadedFile\AbstractUploadedFile`
    - if you override the method, change the parameter type from `Shopsys\FrameworkBundle\Component\UploadedFile\UploadedFile` to `Shopsys\FrameworkBundle\Component\AbstractUploadedFile\AbstractUploadedFile`
- `Shopsys\FrontendApiBundle\Model\Token\TokenAuthenticator::getCredentials()` now returns `null` for an `X-Auth-Token` header without the `Bearer ` prefix and falls back to the `accessToken-<domainId>` cookie for a `POST` request carrying the `X-Domain-Id` header and a same-origin `Origin` header, `supports()` delegates to it
    - update your overrides of these methods accordingly
- `Shopsys\FrontendApiBundle\Model\Security\LoginAsUserFacade::getCurrentAdministratorLoggedAsCustomer()` now reads the administrator from the authenticated `Shopsys\FrontendApiBundle\Model\User\FrontendApiUser` through `Symfony\Component\Security\Core\Authentication\Token\Storage\TokenStorageInterface` instead of parsing the request token, update your override accordingly
- constant `Shopsys\FrontendApiBundle\Controller\SocialNetworkController::ACCESS_TOKEN_COOKIE_NAME` was removed, use `Shopsys\FrontendApiBundle\Model\Token\TokenAuthenticator::getAccessTokenCookieNameForDomainId()` instead
- `Shopsys\FrameworkBundle\Controller\Front\PaymentStatusNotifyController::notifyAction()` now requires a valid order UUID in the `orderIdentifier` query parameter and the GoPay payment id in the `id` query parameter matching one of the order's `Shopsys\FrameworkBundle\Model\Payment\Transaction\PaymentTransaction::$externalPaymentIdentifier`, otherwise it responds with 404
    - if you call the `front_order_payment_status_notify` route from your own payment gateway integration, pass the external payment identifier as the `id` parameter
- `Shopsys\FrontendApiBundle\Model\Resolver\Customer\CustomerRegisteredQuery::couldBeCustomerRegisteredQuery()` no longer calls `isCustomerUserRegisteredQuery()`, both now use the new protected `isCustomerUserRegistered()` method
    - if you override `isCustomerUserRegisteredQuery()`, move the lookup logic to `isCustomerUserRegistered()`
- see #project-base-diff to update your project
