#### CRUD controller actions are declared by the `CrudAction` attribute, custom actions included

- every action of a CRUD controller is a public method marked with `#[CrudAction]`, the built-in actions of `AbstractCrudController` included; declare your own actions the same way in the CRUD controller, its extension, any other controller or an invokable class, see [Custom actions](https://docs.shopsys.com/en/latest/administration/crud-controller/reference/custom-actions/)
    - a custom action must be guarded by one of `#[CanView]`, `#[CanEdit]`, `#[CanCreate]`, `#[CanDelete]`, `#[RequirePermission]`, `#[RequireRole]` or `#[SuperAdminOnly]`, otherwise the container build fails
    - if you override a built-in action (e.g. `editAction()`) in your controller, the attributes of the parent declaration still apply, do not repeat them unless you want to change them
- `Shopsys\AdministrationBundle\Component\Action\AbstractRoutableAction::linkToCrud()` accepts the name of a custom action besides `ActionType`, the parameters were renamed to `$action` and `$parameters` (update named arguments) and the closure may return an array of all route parameters besides the entity ID
- `Shopsys\AdministrationBundle\Controller\CrudControllerTrait::generateCrudUrl()`, `redirectToCrudAction()` and `getCrudRouteName()` accept the name of a custom action as well, an unknown action throws `CrudActionNotFoundException`, a disabled action throws `LogicException`
- `Shopsys\AdministrationBundle\Component\Config\CrudConfig::enableAction()` and `disableAction()` accept the names of custom actions, the constructor has a new `$customActionNames` argument
- removed API, use the replacement:
    - `Shopsys\AdministrationBundle\Component\Router\CrudRouteItem::getPageType()` → `getActionName()`
    - `Shopsys\AdministrationBundle\Component\Action\RouteData\CrudActionRouteData::getActionType()` and `getId()` → `getActionName()` and `getParameters()`
    - `Shopsys\AdministrationBundle\Component\Config\ActionType::toPermission()` and `toAccessControlRules()` → the built-in actions carry `Can*` attributes, use `CrudActionDefinition::$accessControlRules` from `Definition::getAction()`
    - `Shopsys\AdministrationBundle\Component\Crud\Helper\CrudTransformationHelper::generateController()` → `CrudActionDefinition::getControllerReference()`
    - `Shopsys\AdministrationBundle\Component\Router\CrudRouteProvider::DEFAULT_ROUTES_CONFIG` → the paths are declared by the `CrudAction` attributes of `AbstractCrudController`
- changed constructors (update your overrides or manual service definitions): `CrudControllerRegistry` (`$crudActions`), `RouteAccessControlDataProvider` (`CrudControllerRegistry`), `RouteAccessControlSubscriber`, `LiveComponentAccessControlSubscriber` and `LiveComponentAccessControlDataProvider` (`AccessControlRuleFactory`), `CrudRegistryItem` and `Definition` (`$actions`)

#### Security attributes are converted to access control rules without the role registry

- `Shopsys\AdministrationBundle\Component\Security\Attribute\AttributeProcessor` has no constructor dependencies and `processMethod()` returns `AccessControlRuleData[]` instead of `AccessControlRule[]`, bind the roles with `AccessControlRuleFactory::createFromData()`
- the security attributes are looked up along the inheritance chain: an overriding method without attributes keeps the attributes (`Can*`, `RequireRole`, `RequirePermission`, `SuperAdminOnly`, `PublicAccess`, `CsrfProtection`) of the parent declaration and a class-level `#[SuperAdminOnly]` or `#[ForRole]` applies to subclasses as well; a class-level `#[PublicAccess]` applies to the class itself only
- a plain `#[Route]` method in a CRUD controller no longer falls back to the role of the controller, its permission attributes need an explicit role or a class-level `#[ForRole]` like in any other administration controller; declare the method as a custom action (`#[CrudAction]`) to keep it guarded by the role of the CRUD controller
