#### Articles, blog articles and mail templates are edited with the content editor instead of GrapesJS ([#TBD](https://github.com/shopsys/shopsys/pull/TBD))

- the existing GrapesJS HTML is converted to content editor documents by the one-time post-deploy task `migrate_grapesjs_content` (`MigrateGrapesJsContentTask`)
    - `build-deploy-part-3-non-blocking` runs it automatically, `build-dev` and `demo-data` run it as well; to run it manually use `php bin/console deploy:post-deploy:run-tasks`
    - it converts articles, blog article translations, and mail templates that have no `content` yet, images from `content/…` are imported to the media library, the articles and blog articles are then exported to Elasticsearch again
    - a row that cannot be converted is skipped and reported, the other rows are converted; the task only touches rows without `content`, so running it again is safe
    - what could not be converted exactly (dropped products with unknown catalog numbers, images outside of `content/`, unsupported markup) is printed as a table at the end of the task and written to the application log as a warning with the `content_editor_migration` context key; check the converted mail templates and re-save the ones from the table
- the legacy columns `articles.legacy_grapesjs_text`, `blog_article_translations.legacy_grapesjs_description`, and `mail_templates.legacy_grapesjs_body` still hold the original HTML and are not read by the application, they are dropped in the next release:

    ```sql
    ALTER TABLE articles DROP COLUMN legacy_grapesjs_text;
    ALTER TABLE blog_article_translations DROP COLUMN legacy_grapesjs_description;
    ALTER TABLE mail_templates DROP COLUMN legacy_grapesjs_body;
    ```

    - the migration will fail when any row still has `content IS NULL AND legacy_grapesjs_… IS NOT NULL`, so run the task on every environment before the next release

- `ArticleData::$text` was replaced by `$content`, `BlogArticleData::$descriptions` by `$contents`, and `MailTemplateData::$body` by `$content` (a `ContentDocument`); update your data fixtures, imports, and tests
- GraphQL fields `Article.text` and `BlogArticle.text` were replaced by `content` (JSON), update the storefront queries
- `MailTemplateFacade::getWrappedWithGrapesJsBody()` was renamed to `getTemplateWithRenderedContent()` and `getTemplateWrappedWithGrapesBody()` to `withRenderedContent()`
- administrators who can edit articles, blog articles, or mail templates can use the media picker in the editor without any new role, the media rights follow the edit permission of these sections
- replace `Shopsys\FrameworkBundle\Form\GrapesJsType` in your forms with `Shopsys\AdministrationBundle\Form\Admin\Type\ContentEditorType`, GrapesJS itself is removed together with it
- see #project-base-diff to update your project
