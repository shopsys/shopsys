#### Add FedCM (Federated Credential Management) login flow ([#4631](https://github.com/shopsys/shopsys/pull/4631))

- A new GraphQL mutation `LoginWithCredential` enables one-tap sign-in via Google and Seznam without redirecting away from the storefront. It accepts a credential issued by the browser's FedCM flow (JWT id_token for Google, OAuth authorization code for Seznam) and returns the same `LoginResult` contract as the standard `Login` mutation. The mutation input also accepts an optional `nonce` field — the backend verifies it against the id_token `nonce` claim for providers whose credential format carries one (Google), preventing replay attacks. Providers without a nonce claim (Seznam authorization code) intentionally ignore the parameter.
- The `Settings` GraphQL type now exposes a new `fedcmProviders` field returning the FedCM-enabled identity providers (type, clientId, configUrl, autoSelect) for the current domain. It is empty when FedCM is globally disabled, no provider has FedCM enabled, the provider is missing a `configUrl`, or the domain is not in the provider's `enabledOnDomains`.
- `social_network_config.yaml` gained a global `fedcm.enabled` switch and a per-provider `fedcm` section with `configUrl` and `autoSelect`. **All FedCM defaults are off** — existing projects keep their classic redirect login untouched until they explicitly opt in. The per-domain scope reuses the existing `enabledOnDomains` field, no duplication. Add the new keys to your project's `social_network_config.yaml` (see #project-base-diff) and configure `GOOGLE_CLIENT_ID` / `SEZNAM_CLIENT_ID` in your env files for each domain on which you want FedCM enabled.
- The FedCM credential verification is implemented as two HybridAuth subclasses (`Shopsys\FrontendApiBundle\Model\SocialNetwork\Google`, the existing `Seznam`) that now implement a new `FedcmAdapterInterface`. Google verification calls Google's `https://oauth2.googleapis.com/tokeninfo` endpoint, checks the HTTP status code, and validates `aud`/`iss`/`email_verified` (plus `nonce` when supplied) claims; Seznam exchanges the authorization code via the inherited HybridAuth OAuth2 logic and reuses the existing `getUserProfile()`. **No new composer dependencies are introduced** — everything goes through HybridAuth's built-in httpClient.
- `SocialNetworkFacade::login()` is internally refactored to share a `registerOrLoginFromProfile()` step with the new `loginWithCredential()`. The public signature of `login()` is unchanged. If your project overrides `SocialNetworkFacade`, review the refactor: cart-merge / product-list inputs are now method parameters instead of being read from the session inside the post-login step (the redirect-flow `login()` still reads them from the session before calling the shared step, so behaviour is preserved).
- If your project adds new social providers and you want them to participate in FedCM, implement `FedcmAdapterInterface` on the provider subclass (declare `getLoginType()` and `getUserProfileFromFedcmCredential()` with an optional `?string $expectedNonce` parameter), register the class via the `adapter:` key in `social_network_config.yaml`, and add a `fedcm` section. The `FedcmAdapterFactory` will pick it up automatically; if it cannot (e.g. wrong adapter class), it logs a warning to help debug the misconfiguration.
- The `LoginWithCredentialMutation` reuses the same `security.login_throttling.frontend_api.limiter` rate limiter as the standard `LoginMutation`, so FedCM logins share the throttling budget with classic password logins.
- see #project-base-diff to update your project
