#### Protect CSV exports against formula injection ([#4777](https://github.com/shopsys/shopsys/pull/4777))

- `Shopsys\FrameworkBundle\Component\HttpFoundation\CsvResponse` now prefixes exported values starting with `=`, `-`, `+`, `@`, tab, CR or LF with an apostrophe, so spreadsheet software does not evaluate them as formulas
    - if you re-import such an export, strip the apostrophe from the imported values, see `Shopsys\FrameworkBundle\Model\PriceList\PriceListFacade::unescapeFormula()` — a value that really starts with an apostrophe followed by one of those characters cannot be told apart from an escaped one and loses the apostrophe on import
    - only values are escaped, not column names, so escape the column names yourself if they can contain user input
    - in your own CSV exports that do not use `CsvResponse`, add `Symfony\Component\Serializer\Encoder\CsvEncoder::ESCAPE_FORMULAS_KEY => true` to the encoder context, or use `Shopsys\FrameworkBundle\Component\HttpFoundation\StreamedCsvResponse` for large exports (it takes the columns of the whole export from the first row)
- `CsvResponse` now respects the passed `$csvHeaders` that were ignored before because of an inverted condition — check the output of your exports that pass custom headers, their column set and order now follow the passed headers
- if you override `Shopsys\FrameworkBundle\Model\PriceList\PriceListFacade::preProcessCsvRow()`, call the parent implementation or unescape the values yourself, otherwise the price list import keeps the escaping apostrophes
- `Shopsys\FrameworkBundle\Controller\Admin\NewsletterController::streamCsvExport()` was removed and the newsletter export is newly streamed by `StreamedCsvResponse` — if you have overridden it, move your changes into your own `StreamedCsvResponse` descendant
- if you have overridden `Shopsys\FrameworkBundle\Model\Newsletter\NewsletterRepository::getAllEmailsDataIteratorByDomainId()` or `Shopsys\FrameworkBundle\Model\Newsletter\NewsletterFacade::getAllEmailsDataIteratorByDomainId()`, change the return docblock to `iterable<array{email: string, createdAt: string}>` — the scalar hydration returns `createdAt` as a string
- see #project-base-diff to update your project
