#### MCP: SQL validator no longer lets queries read hidden columns or non-exposed tables ([#4955](https://github.com/shopsys/shopsys/pull/4955))

- if your project extends `Shopsys\McpBundle\Component\Database\Query\SqlQueryValidator`, update the signatures of the protected methods you override:
    - `validateSelectStatement()` has a new optional `$inheritedCteRelationsIndexedByNames` parameter and `validateCteDefinitions()` has a new `$inheritedCteRelationsIndexedByNames` parameter - CTEs visible from enclosing queries are passed in it instead of in the outer relations
    - `validateSelectStatementNodes()`, `validateNode()`, `validateChildNodes()` and `validateWrappedNode()` have a new `$visibleCteRelationsIndexedByNames` parameter
    - `validateNode()`, `validateChildNodes()`, `validateWrappedNode()` and `validateColumnReference()` no longer have the `$outputColumnNamesSet` parameter - output column names are accepted only for bare `ORDER BY` items in `validateSortClause()`
    - `getCteDefinitions()` now returns a list of definitions with the `name` key instead of definitions indexed by name, or `null` for a malformed `WITH` clause
    - relations passed in `$relationsIndexedByAliases` now carry a `scopeLevel` key that `resolveUnqualifiedColumnReferenceError()` uses to resolve unqualified columns level by level - keep it when you build or copy relations
- methods `validateUnqualifiedColumnReference()` and `getCteRelationsIndexedByNames()` of `Shopsys\McpBundle\Component\Database\Query\SqlQueryValidator` were removed - unqualified column references are resolved by `resolveUnqualifiedColumnReferenceError()` and visible CTEs are passed in the new parameters instead
