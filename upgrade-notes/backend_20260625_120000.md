#### Automatic domain filter on CRUD Controller list pages ([#XXXX](https://github.com/shopsys/shopsys/pull/XXXX))

- CRUD Controller list pages now automatically detect domain-aware entities and render a domain switcher above the grid:
    - entities with a scalar `domainId` field (e.g. `Order`) have their grid rows filtered to the selected domain
    - entities with a `domains` `OneToMany` association (e.g. `Category`) are not row-filtered (every record exists on every domain); the selected domain's row is `LEFT JOIN`ed under `CrudDomainFilterResolver::DOMAIN_JOIN_ALIAS` so per-domain columns can be shown, and the controller may add its own row filter in `configureQuery()`
- by default the globally selected admin domain is used (`DomainFilterMode::SWITCH`); call `$config->setDomainFilterMode(DomainFilterMode::FILTER)` in `configure()` to use a per-page filter with an extra "all domains" option instead
- if you have a CRUD Controller over a domain-aware entity and do not want this behavior, disable it with `$config->disableDomainFilter()` in the controller's `configure()` method
- for entities that do not match the detected shapes, use `$config->disableDomainFilter()` and filter manually in `configureQuery()` using the resolved `$this->selectedDomainFilterId`
