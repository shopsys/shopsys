#### Multiple currencies per domain ([#{pullRequestId}](https://github.com/shopsys/shopsys/pull/{pullRequestId}))

- the selected currency is persisted in the `currencyCode-{domainId}` cookie and sent to the Frontend API as the `X-Currency-Code` header by the urql client (both on the server and in the browser) — if you have a custom urql client setup, mirror the changes in `urql/createClient.ts`
- the SSR Redis cache key in `urql/fetcher.ts` now contains a currency bucket — without it, cached responses would leak prices between currencies
- a new `CurrencySwitcher` component is rendered in the desktop header and the mobile menu; it renders nothing on domains with a single currency
- `useFormatPrice` returns a formatter accepting an options object with `currencyCode` — components rendering order-scoped prices (order detail, order lists, complaints, personal data export, order confirmation) must pass the `currencyCode` of the order instead of relying on the currently selected currency
- never format prices with `domainConfig.currencyCode` — it is a build-time value; use `settings.pricing.currentCurrencyCode` from the settings query (or the `currencyCode` of the concrete price) instead
- the GraphQL fragments were extended by `currencyCode` fields (prices, orders, pricing settings) — run `pnpm run gql` after merging to regenerate the typed documents
- see #project-base-diff to update your project
