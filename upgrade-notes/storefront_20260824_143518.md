#### Forms can send a honey pot field and report the exceeded submission rate limit ([#{pullRequestId}](https://github.com/shopsys/shopsys/pull/{pullRequestId}))

- `useErrorHandler` applies its `customMessage` option only to errors of type `default`; an error code registered in `utils/errors/applicationErrors.ts` now always shows its own message from `utils/errors/errorMessageMapper.ts`
    - if you relied on `customMessage` replacing the message of every application error, move the wording of the codes you care about into `errorMessageMapper.ts`
- to protect your own form against spam bots, call `useHoneyPot(formProviderMethods)` from `utils/forms/honeyPot.ts` and use both of its return values — pass `renderHoneyPot` to the `Form` component and spread `getHoneyPotInput()` into the variables of the mutation
    - keep the value out of your form type, Yup schema and `*FormMeta` fields, so that it does not become a validated form field
- the new user error code `too-many-form-submissions` is registered in `utils/errors/applicationErrors.ts` as `flash-message` and translated in `utils/errors/errorMessageMapper.ts` — if you maintain your own copies of these files, add the code to both, otherwise it falls through to the generic `Unknown error.` toast
- `ContactContent` shows the success page only when the `ContactForm` mutation returns `true` and shows the form error message when it returns `false`; if you have your own copy of the component, check the returned value the same way, otherwise a failed send still looks like a sent message
- see [Protecting a Form Against Spam](https://docs.shopsys.com/en/latest/cookbook/protecting-a-form-against-spam/) for the whole pattern
- see #project-base-diff to update your project
