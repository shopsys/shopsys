#### access control and admin menu tweaks ([#3933](https://github.com/shopsys/shopsys/pull/3933))

- `role_hierarchy` and `access_control` settings are configured in new `app/config/packages/security.php` file
    - if your IDE does not recognize the `SecurityConfig` class used in the configuration file, be sure to mark the "/var/cache/dev/Symfony" folder as not excluded, see https://symfony.com/doc/current/configuration.html#using-php-configbuilders
    - instead of defining the access control using path regex patterns, you can use the new `#[AccessControlRule]` above particular controller actions
    - if needed, you can still define the access control using path regex patterns in `security.php`
- no longer necessary `MenuItemsGrantedRolesSetting` was removed, the menu items are now removed automatically based on the access control setting
- if you have extended any of `standards*` phing targets, make sure they now depend on the new `access-control-rules-check` target
- if you have extended `tests-acceptance-before` phing target, be sure to add `warmup` target phing call before `test-db-dump` target call
- make sure to use `Symfony\Component\Routing\Attribute\Route` attribute for your routes instead of `Symfony\Component\Routing\Annotation\Route` to have the access control working properly
- if you extend any shopsys controller action, copy the new `#[AccessControlRule]` attribute from the parent class
- `MenuItemsGrantedRolesSubscriber::removeItemFromMenu()` method was removed without replacement
- `Shopsys\FrontendApiBundle\Controller\CustomerUserController` was moved to `Admin` subfolder (`Shopsys\FrontendApiBundle\Controller\Admin\CustomerUserController`) and uses the `#[Route]` and `#[AccessControlRule]` attributes
- if you have added any custom roles in your `App\Model\Security\Roles` class, check the [docs](https://docs.shopsys.com/en/17.0/cookbook/adding-a-new-administration-page/#access-control) for the new way of adding the roles
- see #project-base-diff to update your project
