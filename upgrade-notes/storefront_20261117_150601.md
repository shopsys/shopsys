#### storefront: buttons, text links, hover states and theme colors now follow one system ([#5047](https://github.com/shopsys/shopsys/pull/5047))

- buttons now use one size scale that switches at the `vl` breakpoint (1024px) instead of `sm` (480px): `small`, `medium`, `large` and `xlarge` are 36, 40, 44 and 44px high below 1024px and 36, 40, 48 and 56px from 1024px, with 14, 14, 16 and 16/18px text (`text-xs` is no longer used)
    - review your custom `py-*`, `h-*`, `min-h-*` and `text-*` overrides on `Button`, `SubmitButton` and `LinkButton`
    - use the new `getButtonHeightClassName()` from `components/Forms/Button/buttonUtils.ts` for full-width loading skeletons that stand in for a button; `ProductActionSkeleton` now accepts `buttonSize`
    - when a skeleton stands in for a button that sizes to its label, use the new `SkeletonButton` (`components/Basic/Skeleton/SkeletonButton.tsx`) with the button's label and icons, so the placeholder wraps like the loaded button; the checkout skeletons use it through `SkeletonModuleOrderAction` and `SkeletonModuleProductDetailAddToCart` renders the translated Add to cart label
    - use `size="large"` for the main form submit buttons and content calls to action, `size="xlarge"` for purchase actions and `small` only in compact places; give buttons placed side by side the same size and express their priority by `variant`
    - the `PageHero` action is now `large`, and the checkout "Back" button in `OrderAction` is now `xlarge` like the next-step button
    - `Spinbox` button sizes now match the buttons of the same size through `getButtonHeightClassName()`, so the quantity controls replace the add-to-cart button without a jump; the default `Spinbox` size (`large`) grows from 36/40px to 44/48px, so check your own spinboxes (the cart page `Spinbox` now uses `size="medium"`, and `ProductDetailAddToCart` no longer forces 56px buttons on its quantity controls)
    - the "Choose" button of a main variant in `ProductAction` now takes `buttonSize` like the other product actions
    - the two buttons of `AddToCartPopup` are stacked and full width below 480px, so their labels do not wrap
    - the icon of a `medium` button stays 16px on every width (`getButtonIconClassName()` no longer switches it to 20px at `md`)
- `Button`, `LinkButton` and `Link` with `isButton` have the variants `primary`, `secondary`, `outline`, `ghost`, `danger` and `inverted`; the variant gives the structure and the `--color-button-<variant>-*` tokens give the color
    - `secondary` is a new tonal button: the `secondary-100` surface with the default text color, darker on hover and press; it replaces nothing, so choose it where an action should stand out without competing with `primary` (e.g. add to cart next to a watchdog)
    - the former `secondary` button is now `outline`: a white surface with a 1px `neutral-300` line and the default text color, hover and press darken the surface to `background-more` and `background-most`; replace `variant="secondary"` with `variant="outline"` where you want the neutral look
    - `tertiary` was renamed to `ghost`; replace `variant="tertiary"` and `buttonVariant="tertiary"`, and the `--color-button-tertiary-*` tokens with `--color-button-ghost-*`
    - the former `--color-button-secondary-*` tokens are now `--color-button-outline-*`; `Pagination` and `MobileSortingActions` use them directly
- the `hasDisabledCursor` prop was removed from `Button`, `LinkButton`, `SubmitButton` and `OrderAction`, and `OrderAction` no longer accepts `hasDisabledLook`
    - the disabled cursor is now shown only on natively disabled buttons (`disabled:cursor-no-drop`); remove the prop from your calls
    - `getButtonClassName()` no longer accepts the fourth `hasDisabledCursor` argument
- buttons on invalid forms stay enabled and no longer get the disabled look; the form shows its errors after the click
    - use `hasDisabledLook` only for a button that cannot be used or whose action is in progress
    - the transport and payment step keeps its next-step button enabled without a selected transport or payment and shows the validation popup after the click; it is disabled only while the cart is being updated
    - the checkout "Submit order" button no longer gets `hasDisabledLook` on an invalid form, and the "Create account" button after an order no longer gets it after a failed registration, so the customer can try again
- text links and text actions now get their look from `variant` and `tone`, available on `Link`, the new `TextButton` (`components/Basic/TextButton/TextButton.tsx`) and as `getLinkClassName()` in `components/Basic/Link/linkUtils.ts`
    - `variant: 'text'` (the default) is a link in the content of the page: it keeps the font of the text and is always underlined
    - `variant: 'action'` is a text action (show more, open description, edit, review count): 14px `font-ui` (500), an optional 16px trailing icon, always underlined; it is the default of `TextButton`
    - `variant: 'navigation'` is a link among similar links (menu, footer column, breadcrumbs): underlined on hover only
    - `tone` is `accent` (the default of text and action links), `default` (the default of navigation links), `subtle` (always underlined) or `inverted` for dark backgrounds
    - an action that only looks like a link is a `TextButton`; show more and show less actions use the new `ShowMoreButton` (`components/Basic/ShowMoreButton/ShowMoreButton.tsx`) instead of a ghost (formerly tertiary) `Button` with an arrow icon or `ShowAllButton`, which was removed from `components/Blocks/Product/Filter/FilterElements.tsx`
    - cards and tiles are not text links: they never get an underline and react to hover by their surface; the header main menu, phone and icon menu change color only
    - replace custom `underline`, `no-underline` and `text-link-*` classes on your links with `variant` and `tone`; `vitest/conventions/linkClassNames.test.ts` reports hand-written link styles in `components`
    - `linkPlaceholderTwClass` was removed from `components/Basic/Link/Link.tsx`; use `getLinkClassName()`
    - a link opening in a new tab no longer shows an icon; `Link` and `ExtendedNextLink` add a visually hidden "Open in new tab" through the new `NewTabHint` (`components/Basic/Link/NewTabHint.tsx`) and append it to an `aria-label` through `useGetNewTabAriaLabel()`; use both for your own `<a target="_blank">`
- checkboxes, radio buttons, switches and color swatches now show the same hover ring through the new `choice-hover` variant (`styles/custom.css`)
    - a choice whose label is apart from its indicator marks its wrapper with `data-choice-hover-scope`, so hovering the label shows the ring
    - the ghost `IconButton` now darkens its background and colors its icon on hover and press
- `Link` now forwards all native anchor attributes and events (e.g. `aria-label`, `onKeyDown`), which were previously dropped
    - an `aria-label` now replaces the visible text of the link for screen readers, so remove it where the text already says where the link leads; the privacy policy and terms links in the registration, watchdog, newsletter and order consents no longer pass one, and the `Go to privacy policy article` and `Go to terms and conditions article` translations were removed
    - `ExtendedNextLink` no longer starts the page loading state when the click is cancelled by `preventDefault()`, the link downloads a file or the browser opens it elsewhere (Ctrl, Cmd, Shift or Alt click, middle click, a `target` other than `_self`); it now calls your `onClick` for these clicks too
    - the main menu, the More menu, the login dropdown and the product variants popup close through `onNavigate` of their links instead of `onClick`, because `onNavigate` runs only when the link navigates in the same tab, so a category opened in a new tab keeps the menu open; pass your own close handlers to `onNavigate` the same way
- the CMS button (`.gjs-button-link` in `styles/user-text.css`) now has the height and text size of the large button
    - run `pnpm compile-tailwind-for-admin` to regenerate `public/tailwind-for-admin/style.css`
- the theme colors in `styles/theme.css` are now a generated palette with semantic tokens grouped into commented blocks (palette, foundations, interaction, components, feedback, domain)
    - the theme is set by three key colors in `scripts/generateColorPalette.mjs`: `primary` (actions, links, the brand), `secondary` (tonal actions; by default the primary color) and `neutral` (surfaces, borders and muted text); run `pnpm run generate-color-palette` after changing them; `red`, `orange` and `green` stay for the states
    - every palette has steps 50–950 built in OKLCH with its key color at step 500, lighter steps below and darker steps above; the light neutral steps stay close to gray
    - the `brand-*` palette was merged into `primary-*`, and the `gray-*` and blue-gray `secondary-*` palettes into `neutral-*`; `secondary-*` is now the second key color
    - the `primary-*` steps keep their colors (e.g. `primary-500`); the former brand and status colors moved to step 500, so update the classes that use palette steps directly: `brand-600` → `primary-500`, `brand-700` → `primary-600`, `brand-800` → `primary-700`, `brand-500` → `primary-400`, `red-700` → `red-500`, `red-800` → `red-600`, `red-900` → `red-700`, `green-700` → `green-500`, `green-800` → `green-600`, `orange-700` → `orange-800`, `gray-*` and `secondary-*` → `neutral-*` (with `gray-400` → `neutral-300` and `gray-900` → `base-black`); prefer a semantic token where one exists
    - semantic tokens keep their names; the hovered state of an interactive token is now one step darker than its default and the active state two steps darker
    - removed tokens no component used: `button-{primary,secondary,tertiary,danger,inverted}-icon-*` (button icons take the text color), `toast-{bg,border,icon,text}-default`, `fill-default`, `fill-more`, `fill-most`, `fill-accent`, `fill-error`, `link-visited`, `icon-primary`, `input-bg-active`, `input-bg-error`, `input-text-warning`, `input-text-error`, `input-placeholder-error`, `background-success-more`, `background-warning-more` and `tag-border-*`
    - `input-glow-active` was replaced by `input-glow-hovered`, which the hover ring of checkboxes, radio buttons and switches now uses
    - added `link-inverted-active`, `icon-success-inverted`, `flag-bg-blog`, `flag-bg-highlight`, `rating-fill` and `rating-empty`
    - `text-disabled` is now the disabled text color (`neutral-400`) instead of a dark gray; use `text-less` for muted labels
- components now use the semantic tokens instead of palette colors
    - the focus highlight uses `focus-background` and `focus-ring` instead of `orange-500`
    - `Tag` uses the `tag-*` tokens, and a disabled tag uses `tag-bg-disabled` and `tag-text-disabled` instead of `opacity-50`
    - the required field asterisk uses `input-required-star`, links use `link-active` and `link-inverted-active` for their active state, and review stars use `rating-fill` and `rating-empty`
    - run `pnpm compile-tailwind-for-admin` to regenerate `public/tailwind-for-admin/style.css`
- radii now come from one switch, `--radius-base` (10px) in `styles/theme.css`, and four role tokens that are its multiples: `--radius-detail` (0.6×), `--radius-control` (1×), `--radius-card` (1.2×) and `--radius-surface` (1.6×)
    - the component tokens follow the roles: `--radius-button`, `--radius-input` and `--radius-counter` use `control`, `--radius-tag` stays `full`, so tags (filters, status tabs, selected values) stay pills, `--radius-checkbox` and `--radius-flag` use `detail`, `--radius-toast` uses `surface` and `--radius-product-card` uses `card`
    - components use `rounded-<role>` and the component tokens instead of `rounded-sm`, `-md`, `-lg`, `-xl` and `-2xl`; `Tag` uses `rounded-tag` and product list items use `rounded-product-card`; replace the default Tailwind radii in your components the same way
    - `styles/custom.css` no longer overrides `--radius-sm` to 3px, and the duplicate `--radius-xl` declaration was removed
    - an `IconButton` with `shape="rounded"` uses `rounded-button`, and the new `shape="inset"` uses `rounded-detail` for an icon button inside a field
    - `twMergeCustom()` knows the role and component radius tokens
- the info toast was renamed to the warning toast, because every message shown with it was a warning with the warning icon and colors
    - `showInfoMessage()` (`utils/toasts/showInfoMessage.tsx`) is now `showWarningMessage()` (`utils/toasts/showWarningMessage.tsx`), and `showMessage()` takes `'warning'` instead of `'info'`
    - the toast TID `toast_info` is now `toast_warning`, the Cypress helper `checkAndHideInfoToast()` is now `checkAndHideWarningToast()` and the CSS class `.Toastify__toast--info` in `styles/base.css` is now `.Toastify__toast--warning`
- the styleguide (`/styleguide`) is now split into sections with a navigation and shows the current viewport, colors from `styles/theme.css`, the radius tokens and the variants, states and sizes of buttons and links
    - `make generate-icons-for-styleguide` now generates only the icon grid, which `StyleguideContent` places into its section; update the generator in your `Makefile` if you regenerate the icons
    - `ErrorDebugSettingsContent` is now a section of the styleguide instead of a separate block under it; it no longer checks the environment or wraps itself in `Webline`, `StyleguideContent` adds it only in development, so guard it with `isEnvironment('development')` if you render it anywhere else
