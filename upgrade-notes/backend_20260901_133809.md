#### admin assets are now built by Rsbuild with Symfony Reprise instead of Webpack Encore ([#4818](https://github.com/shopsys/shopsys/pull/4818))

- `shopsys/framework` and `shopsys/administration` now require `symfony/reprise` and the administration layout renders assets with the `reprise_entry_*` Twig functions — register `Symfony\Reprise\RepriseBundle`, remove `symfony/webpack-encore-bundle`, and replace every `encore_entry_link_tags()` / `encore_entry_script_tags()` call in your own templates (e.g. an overridden `@ShopsysAdministration/layout/base.html.twig`) with `reprise_entry_link_tags()` / `reprise_entry_script_tags()`
- `Shopsys\FrameworkBundle\Form\WysiwygTypeExtension` constructor argument `string $entrypointsPath` was replaced by `Symfony\Reprise\Asset\EntrypointsLookupInterface $entrypointsLookup` and `Symfony\Component\Asset\Packages $packages`, and the `shopsys.json_entrypoints_path` parameter was removed — update `new WysiwygTypeExtension(...)` calls (e.g. in tests) and drop any service definition override passing `$entrypointsPath`
- import jQuery explicitly (`import $ from 'jquery';`) in every JavaScript file that relied on Encore's `autoProvidejQuery()` and replace the bare `jQuery` global with `$` — only `window.$` / `window.jQuery` set by `assets/js/jQuery/registerJquery.js` remain, for third-party plugins
- rewrite inline `<script>` blocks in your Twig templates that use `$` / `jQuery` to plain DOM APIs — the admin bundles are ES modules and run after inline scripts, see `Shopsys\FrameworkBundle\Component\CKEditor\CKEditorRendererDecorator::renderWidget()` and `@ShopsysAdministration/content/promoCode/listMassGeneratedBatch.html.twig` for the pattern
- add the `?raw` query to SVG imports that relied on the webpack `asset/source` rule (`import Icon from 'icons/tabler/check.svg?raw';`)
- `select2` and `jquery-hoverintent` were removed from the `@shopsys/framework` npm dependencies (and `jquery.cookie` from project-base) — add them to your `package.json` if your own code uses them
- `js/common/plugins/jquery.fix.clone.js` was removed from `@shopsys/framework` — copy the plugin into your project if you imported it
- stylelint no longer runs as part of the asset build (`stylelint-webpack-plugin` was removed) — run the `stylelint` phing target instead
- use `npm run dev-server` (Rsbuild dev server with hot module replacement on port `35729`) to get the browser updated automatically — `npm run watch` still rebuilds the bundles, but LiveReload was removed
- if you customized `webpack.config.js`, port your customizations to `rsbuild.config.ts` — entries, aliases, and static copies have direct equivalents, webpack loaders and plugins do not carry over
- if you register your own Stimulus controllers with `require.context('@symfony/stimulus-bridge/lazy-controller-loader!...')`, register them with `import.meta.webpackContext()` on the app returned by `startStimulusApp()` from `@symfony/reprise/stimulus` (see `assets/stimulus_bootstrap.js`)
- if you override `Shopsys\FrameworkBundle\Component\HttpFoundation\SecurityHeadersResponseListener::getDevelopmentCspAppendices()`, add `http://localhost:35729` and `ws://localhost:35729` to `default-src`, `style-src`, and `connect-src` so the Rsbuild dev server and its HMR websocket are allowed in development
- if your PHP code parses `web/build/entrypoints.json` itself, use `Symfony\Reprise\Asset\EntrypointsLookupInterface` instead — the file format is now owned by Reprise
- if you resolve built assets through `asset()` and the JSON manifest, adjust the keys — they are now prefixed with `build/` (`manifestKeyPrefix` in `rsbuild.config.ts`)
- if you need to support browsers older than Rsbuild's SWC defaults, add a `browserslist` configuration — the `core-js`, `regenerator-runtime`, and `es6-promise` polyfills and the Babel `safari >= 8` target were dropped
- if your deployment does not use the phing `build*` targets, build the assets (`npm run build`) before `cache:warmup` — `reprise.cache: true` in `config/packages/prod/reprise.yaml` compiles `entrypoints.json` into the container cache
- see #project-base-diff to update your project
