#### restrict the file manager (elFinder) to the WYSIWYG directory ([#0000](https://github.com/shopsys/shopsys/pull/0000))

- the file manager is no longer able to access the whole project directory, any path (hash) sent by the client that points outside of the configured root is refused
    - elFinder now works with the new `wysiwyg_filesystem` service (`Shopsys\FrameworkBundle\Component\Filesystem\DirectoryRestrictedFilesystem`) instead of `main_filesystem`, change `filesystem: 'main_filesystem'` to `filesystem: 'wysiwyg_filesystem'` in all roots in `app/config/packages/fm_elfinder.yaml`
    - `Shopsys\FrameworkBundle\Component\Filesystem\Flysystem\VolumeDriver::decode()` returns `false` for paths outside of the volume root
    - `VolumeDriver::tmb()` no longer tries to copy a fallback icon when a thumbnail cannot be created, the client shows the icon of the file type instead
- the file manager routes now require an administrator who can create or edit in at least one section (`Shopsys\FrameworkBundle\Component\Security\AccessControl\FileManagerAccessChecker`), administrators with only view/delete permissions get 403
    - `Shopsys\FrameworkBundle\Controller\ElFinder\ElfinderController` has a new constructor parameter `FileManagerAccessChecker`
    - if you changed the root `path` in `fm_elfinder.yaml`, set the same directory as `$allowedDirectory` of the `wysiwyg_filesystem` service
- see #project-base-diff to update your project
