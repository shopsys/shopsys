#### transports and transport groups now support SVG logos ([#5058](https://github.com/shopsys/shopsys/pull/5058))

- Before upgrading `shopsys/framework`, deploy the uploaded SVG rules from `docker/nginx/nginx.conf` or `app/orchestration/kubernetes/configmap/nginx.yaml` to every endpoint that serves uploaded images.
    - Apply the `$uploaded_svg_content_security_policy` map and its `add_header Content-Security-Policy ... always` directive so the browser blocks scripts when an uploaded logo is opened directly. Configure equivalent response headers on custom web servers and CDNs.
    - Include `svg` in the image location and anchor the extension at the end of the path with `$`. Apply the `$image_resize_args` map and use it for the resizer condition so SVG requests with query parameters also serve the original file.
    - Verify that a public logo URL returns `image/svg+xml` and the sandbox CSP both with and without `?width=64`.
- SVG uploads containing active content or external references are rejected. Re-export the logo as a self-contained, static SVG. The order confirmation email shows the transport name without its logo when the transport uses SVG. Apply the same condition to project overrides of `Mail/Order/transportInfo.html.twig`.
- see #project-base-diff to update your project
