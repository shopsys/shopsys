#### Add FedCM (One Tap) login on the storefront ([#4631](https://github.com/shopsys/shopsys/pull/4631))

- A new `FedcmOneTap` component is globally mounted in `AppPageContent` (client-only via `next/dynamic`) and triggers the browser's FedCM account picker for unauthenticated users on every page load — once per session, then with a 7-day cooldown after dismissal so the prompt stays out of the way after a user declines it. The component reads the new `settings.fedcmProviders` field from the existing `SettingsQuery` cache (no extra round-trip) and falls back silently when no provider is enabled, the user is already logged in, or the browser does not support the `IdentityCredential` API. **FedCM is off by default in `social_network_config.yaml`** — opt in per provider before the prompt will appear.
- A nonce is generated client-side via `crypto.randomUUID()` (with a `getRandomValues` fallback) before each `navigator.credentials.get()` call and passed both to the FedCM provider config and to the `LoginWithCredential` mutation, so the backend can reject replayed id_tokens. The `autoSelect` config flag is honoured: when every enabled provider has `autoSelect: true`, the browser is invoked with `mediation: 'silent'` (returning users sign in without an explicit prompt).
- A new `useLoginWithCredential` hook mirrors `useLogin` for the federated flow: it calls the new `LoginWithCredential` GraphQL mutation, persists tokens via `setTokensToCookies`, and reuses the exported `useHandleActionsAfterLogin` (broadcast cross-tab reload, persist-store cleanup) so post-login UX matches the existing email/password and social-redirect flows.
- The `SettingsQuery.graphql` now requests `fedcmProviders { type clientId configUrl autoSelect }` and the new `LoginWithCredentialMutation.graphql` accepts a `nonce` variable. Run `make generate-schema` and `pnpm run gql` after pulling so the generated `*.generated.tsx` and `types.ts` reflect the new fields.
- The FedCM identity-provider configuration files (`accounts.google.com/gsi/fedcm.json`, `login.szn.cz/fedcm/config.json`) are hosted by the identity providers themselves. The storefront does not host any `.well-known/web-identity` of its own — it only references the IdP URLs via `configURL` passed into `navigator.credentials.get()`.
- When Google and Seznam are both enabled, `FedcmOneTap` infers which provider issued the returned credential from the token shape (JWT = Google id_token, plain string = Seznam authorization code). If your project adds another JWT-based FedCM IdP, revisit `inferProviderTypeFromToken` so the discriminator stays unambiguous.
- If your project customises `AppPageContent`, port the `<FedcmOneTap />` mount (see #project-base-diff) so the prompt is available across all non-error routes. If you only want FedCM on the login page, mount it there instead of in `AppPageContent`.
