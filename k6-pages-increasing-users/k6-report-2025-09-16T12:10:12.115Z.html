🔍 http_req_duration

Total request time - Complete time from sending request to receiving full response. This is what users experience.

💡 How to Improve:
  • Enable Next.js caching: Use fetch() with cache options
  • Optimize images: Use next/image with WebP/AVIF formats
  • Add CDN: Serve static assets from edge locations
  • Database optimization: Add indexes, connection pooling
  • Code splitting: Use dynamic imports for large components

⏱️ http_req_waiting (TTFB)

Server processing time - Time spent waiting for server response. Measures your backend performance.

💡 How to Improve:
  • Database queries: Add indexes, optimize N+1 queries
  • Server Components: Move data fetching to server side
  • Caching layers: Implement Redis for frequent queries
  • API optimization: Reduce payload size, batch requests
  • Resource allocation: Increase server CPU/memory

🔗 http_req_connecting

Connection time - Time to establish TCP connection. High values indicate network or server capacity issues.

💡 How to Improve:
  • Connection pooling: Reuse existing connections
  • Keep-alive headers: Maintain persistent connections
  • Load balancer: Distribute connections across servers
  • Geographic proximity: Deploy closer to users
  • Server capacity: Scale up connection limits

📤 http_req_sending

Request send time - Time to send request to server. Usually very low for GET requests.

💡 How to Improve:
  • Network optimization: Use HTTP/2 for multiplexing
  • Request size: Minimize headers and body content
  • Connection reuse: Enable keep-alive connections
  • Geographic location: Deploy servers closer to users
  • Quality of Service: Ensure stable network connection

📥 http_req_receiving

Response download time - Time to download response body. High values suggest large responses or slow network.

💡 How to Improve:
  • Enable compression: Use gzip/brotli for text responses
  • Optimize bundle size: Remove unused code, tree shaking
  • Image optimization: Compress images, use modern formats
  • Streaming SSR: Send HTML chunks as they're ready
  • Reduce payload: Send only necessary data to client

🚫 http_req_blocked

DNS lookup time - Time spent on DNS resolution and connection setup. Should be minimal after first request.

💡 How to Improve:
  • DNS optimization: Use fast DNS providers (Cloudflare, Google)
  • DNS caching: Set appropriate TTL values
  • Connection pooling: Reuse existing connections
  • CDN usage: Reduce initial connection overhead
  • Preconnect hints: Use rel="preconnect" for key domains

🔄 iteration_duration

Full test cycle time - Complete time for one user iteration including request + think time.

💡 How to Improve:
  • Reduce overall latency: All above optimizations combined
  • Parallel processing: Handle multiple requests concurrently
  • User flow optimization: Minimize required interactions
  • Progressive enhancement: Load critical content first
  • Realistic think time: Adjust test parameters for real usage
