# CSRF Protection

Shopsys Platform uses multiple CSRF protection mechanisms.  
This page explains route-level CSRF protection (`protectedUrl` + `#[CsrfProtection]`) and other CSRF usages in the project.

## Route-level CSRF protection

Route-level protection in administration is based on:

- `#[CsrfProtection]` attribute on controller actions
- `routeCsrfToken` request parameter
- token ID format `route_<route_name>`

### How `#[CsrfProtection]` works

The attribute itself is a marker:

- [`packages/framework/src/Component/Router/Security/Attribute/CsrfProtection.php`]({{github.link}}/packages/framework/src/Component/Router/Security/Attribute/CsrfProtection.php)

Validation is handled by [`RouteCsrfProtector`]({{github.link}}/packages/framework/src/Component/Router/Security/RouteCsrfProtector.php), which is a `KernelEvents::CONTROLLER` subscriber.

For protected actions it:

1. reads `routeCsrfToken` from query parameters (GET) or request body (POST),
2. computes token ID as `route_<current_route_name>`,
3. validates the token via Symfony CSRF token manager,
4. throws `BadRequestHttpException` when token is missing/invalid.

### How `protectedUrl` works

Twig function `protectedUrl` is implemented in:

- [`packages/framework/src/Twig/CsrfExtension.php`]({{github.link}}/packages/framework/src/Twig/CsrfExtension.php)

It generates an absolute URL for a route and automatically appends:

- `routeCsrfToken=<token_for_route>`

Example:

```twig
{{ protectedUrl('admin_store_setdefault', { id: store.id }) }}
```

Use it for links that call actions protected by `#[CsrfProtection]`.

## Other route-token usages (without `protectedUrl`)

Besides `protectedUrl`, tokens are also attached in several other ways:

- **Grid action links** (`delete`, `reset password`) in
  [`ActionColumn`]({{github.link}}/packages/framework/src/Component/Grid/ActionColumn.php)
- **CRUD action links** generated by
  [`packages/administration/src/Twig/ActionExtension.php`]({{github.link}}/packages/administration/src/Twig/ActionExtension.php)
  (adds token automatically when target CRUD action is `#[CsrfProtection]`)
- **Confirm-delete modals** in
  [`ConfirmDeleteResponseFactory`]({{github.link}}/packages/framework/src/Component/ConfirmDelete/ConfirmDeleteResponseFactory.php)
- **Manual Twig token composition** using `csrf_token()` with route token ID prefix `route_...`, for example:
  [`packages/administration/templates/form/content/customer/customerUserListType.html.twig`]({{github.link}}/packages/administration/templates/form/content/customer/customerUserListType.html.twig)

## Other CSRF protection mechanisms in the platform

### Symfony form CSRF protection

Global framework CSRF is enabled:

- [`project-base/app/config/packages/framework.yaml`]({{github.link}}/project-base/app/config/packages/framework.yaml)

Most Symfony forms are protected by default. Some forms explicitly disable CSRF when they are GET/search forms, for example:

- [`packages/framework/src/Form/Admin/QuickSearch/QuickSearchFormType.php`]({{github.link}}/packages/framework/src/Form/Admin/QuickSearch/QuickSearchFormType.php)
- [`packages/framework/src/Model/AdvancedSearch/AdvancedSearchFormFactory.php`]({{github.link}}/packages/framework/src/Model/AdvancedSearch/AdvancedSearchFormFactory.php)

Some forms use an explicit token ID, for example:

- [`packages/framework/src/Form/Admin/Product/ProductFormType.php`]({{github.link}}/packages/framework/src/Form/Admin/Product/ProductFormType.php)

### Security firewall login/logout CSRF

Administration authentication uses Symfony Security CSRF settings:

- login CSRF parameter
- logout CSRF token ID (`admin_logout`)

See:

- [`project-base/app/config/packages/security.yaml`]({{github.link}}/project-base/app/config/packages/security.yaml)
- logout route path with `{_csrf_token}` parameter:
  [`project-base/app/config/shopsys-routing/routing_front_en.yaml`]({{github.link}}/project-base/app/config/shopsys-routing/routing_front_en.yaml)
- administration logout link token usage:
  [`packages/administration/templates/layout/layout.html.twig`]({{github.link}}/packages/administration/templates/layout/layout.html.twig)

## Practical recommendation

For administration state-changing route actions:

1. mark action with `#[CsrfProtection]`,
2. generate links via `protectedUrl(...)` when possible,
3. when custom rendering is needed, pass `routeCsrfToken` manually using `RouteCsrfProtector::CSRF_TOKEN_REQUEST_PARAMETER` and route token ID (`route_<route_name>`).
