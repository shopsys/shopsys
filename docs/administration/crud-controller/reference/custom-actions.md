# Custom actions

Besides the built-in actions (`list`, `detail`, `create`, `edit`, `delete`) a CRUD controller can have any number of custom actions, e.g. `approve` of a product review.
A custom action is a controller method marked with the `#[CrudAction]` attribute.
The CRUD controller knows about the action, so the same infrastructure as for the built-in actions applies:

- the route is generated by the CRUD routing under the URL of the CRUD controller (including its `setRoutePrefix()`),
- the action is guarded by the role of the CRUD controller with the permission you declare,
- the action can be linked from the grid and the pages with `linkToCrud()`, links to unknown actions fail and links to disabled actions are hidden,
- the action can be disabled together with the controller or on its own (e.g. by an extension).

Custom actions are commands (a POST with a redirect, a download, ...). They have no title or breadcrumb, a custom action rendering a page takes care of those itself.

The built-in actions are declared the same way in `AbstractCrudController` (e.g. `#[CrudAction(path: '/edit/{id}')]` with `#[CanEdit(methods: [HttpMethod::POST])]` and `#[CanView(methods: [HttpMethod::GET])]` on `editAction()`), so there is a single mechanism for routing and access control of all CRUD actions.
An overriding method in your controller keeps the attributes of the parent declaration.

## Declaring an action

```php
use Shopsys\AdministrationBundle\Component\Attributes\CrudAction;
use Shopsys\FrameworkBundle\Component\Router\Security\Attribute\CsrfProtection;
use Shopsys\FrameworkBundle\Component\Security\Attribute\CanEdit;

#[CrudController(ProductReview::class)]
class ProductReviewController extends AbstractCrudController
{
    #[CrudAction]
    #[CanEdit]
    #[CsrfProtection]
    public function approveAction(int $id): RedirectResponse
    {
        $productReview = $this->getCrudEntity($id);
        $this->productReviewFacade->approve($productReview);
        $this->addSuccessFlashTwig(t('Review of <strong>{{ name }}</strong> was approved.'), ['name' => $productReview->toHumanReadable()]);

        return $this->redirectToCrudAction(ActionType::LIST);
    }
}
```

The action can be declared in any of these places:

| Place                                                     | Target CRUD controller                                      |
| --------------------------------------------------------- | ----------------------------------------------------------- |
| method of the CRUD controller                             | the controller itself                                       |
| method of an extension (`#[CrudControllerExtension]`)     | the controller the extension extends                        |
| method of any other controller                            | must be set: `#[CrudAction(crudController: X::class)]`      |
| invokable class (attribute on the class, `__invoke()`)    | must be set, the name must be set as well                   |

The permission attributes target methods, so on an invokable class they belong to `__invoke()` (only `#[SuperAdminOnly]` and `#[PublicAccess]` may be on the class).

A class outside a `Controller/` directory does not need any service configuration, the attribute registers it as a controller.

### Name and route

- **Name** defaults to the method name without the `Action` suffix in snake_case (`sendEmailAction` → `send_email`). It must match `^[a-z][a-z0-9_]*$` and must not be a built-in action name. The route is named `admin_crud_<controller>_<name>`.
- **Path** defaults to `/<name>` followed by a placeholder for every required scalar parameter of the method, in their order (`moveAction(Request $request, int $id, int $position)` → `/move/{id}/{position}`). It is appended after the CRUD controller URL (`/admin/[prefix/]product-review`). A custom path must contain a placeholder for every such parameter, the other placeholders end up in the request attributes as usual.
- **Method parameters** are resolved by Symfony like in any other controller: `Request`, services, entities and parameters mapped by attributes (`#[MapQueryParameter]`, `#[MapEntity]`, ...) are not route placeholders, neither are parameters with a default value.
- An action whose path contains `{id}` works with a single record, `generateCrudUrl()` and `linkToCrud()` expect the entity or its ID for it. `linkToCrud()` accepts a closure returning either the ID or an array of all route parameters.
- **Route options** known from the Symfony `#[Route]` attribute can be set: `methods`, `requirements`, `defaults` and `condition`. The defaults `_controller` and `_crud_*` are reserved.

```php
#[CrudAction(name: 'export', path: '/export.{_format}', methods: ['GET'], requirements: ['_format' => 'csv|xml'], defaults: ['_format' => 'csv'])]
#[CanView]
public function exportAction(string $_format): Response
```

### Permissions

Every custom action must be guarded by one of `#[CanView]`, `#[CanEdit]`, `#[CanCreate]`, `#[CanDelete]`, `#[RequirePermission]`, `#[RequireRole]` or `#[SuperAdminOnly]`, a missing attribute fails the container build.
`#[SuperAdminOnly]` on the handling class (e.g. the CRUD controller itself) applies to the action as well, `#[PublicAccess]` makes it public.

The role of a `Can*` attribute without an explicit role is resolved in this order: the `#[ForRole]` attribute of the handling class, then the role of the CRUD controller.
The role of the CRUD controller then offers the permission even when the corresponding built-in action is disabled, so e.g. `#[CanEdit]` on `approve` makes the `EDIT` permission available on the role of product reviews even with `editAction` disabled.
Different actions can require different permissions. An attribute with an explicit role (`#[CanEdit(role: 'ROLE_MODERATOR')]`) or a handling class with `#[ForRole]` guards the action by that role and does not influence the role of the CRUD controller.

### Validation at build time

All declarations are validated when the container is compiled, so a mistake shows up immediately: unknown or missing target controller, a name clashing with another action of the same controller or with a built-in action, a path not matching the `$id` parameter, a reserved route default, a non-public method or a missing access control attribute.

!!! note

    The routes and the access control rules are cached outside the `dev` environment. Run `cache:clear` after adding or changing a custom action, the same way as after changing the CRUD configuration.

## Working with the action

### Linking to the action

`linkToCrud()` accepts the name of a custom action the same way as a built-in `ActionType`. Labels and icons are configured in PHP so they are translated via `t()`.

```php
protected function configureDatagrid(Datagrid $datagrid): void
{
    $datagrid->actions()->add(
        RowAction::create('approve', t('Approve'), 'check')
            ->linkToCrud(self::class, 'approve', fn (array $row) => (int)$row['id'])
            ->displayIf(fn (array $row) => $row['statusValue'] === ProductReviewStatusEnum::STATUS_PENDING)
            ->setConfirmMessage(t('Approve this review?')),
    );
}

protected function configureActions(ActionsConfig $actions): void
{
    $actions->add(
        ActionType::EDIT,
        Action::create('approve', t('Approve'))
            ->linkToCrud(self::class, 'approve', fn (ProductReview $review) => $review->getId()),
    );
}
```

A link to an action that does not exist throws `CrudActionNotFoundException` when it is rendered. A link to a disabled action is hidden.
The CSRF token of a `#[CsrfProtection]` action is appended automatically.

### Helpers in the controller and its extensions

The [helper methods](crud-controller.md#helper-methods) accept custom action names as well:

```php
$this->generateCrudUrl('approve', $productReview);   // URL including the CSRF token
$this->redirectToCrudAction('approve', $id);
$this->getCrudEntity($id);                           // loads the record through the registered handler
```

A controller outside the CRUD controller and its extensions gets the `Definition` as well when it implements `CrudDefinitionAwareInterface` (the easiest way is to use `CrudControllerTrait`).

### Disabling the action

```php
// in configure() of the controller or of an extension
$config->disableAction('approve');
```

A disabled action has no route, its links are hidden and its permission is not required by the role. A fully disabled CRUD controller (`$config->disable(true)`) disables its custom actions as well.
